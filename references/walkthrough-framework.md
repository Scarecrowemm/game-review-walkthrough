# 四层攻略框架

攻略面向的是**此刻卡住、正握着手的玩家**。他的耐心以秒计，所以每一层都要回答他当下那一秒的问题，不写他没问的东西。

四层的分工是硬的，不要互相渗透：

| 层 | 回答的问题 | 读者状态 | 粒度上限 |
|----|-----------|----------|----------|
| A 主线路线图 | "我现在该往哪推进？" | 正常推进 | 章节级，不含走位 |
| B 卡关点 | "我过不去，卡在哪了？" | 受挫 | 机制级 + 步骤 |
| C BOSS | "这个 BOSS 怎么读怎么打？" | 受挫且重复失败 | 阶段级 + 帧/秒级窗口 |
| D 隐藏要素 | "我漏了什么？还能补吗？" | 已通过或准备二周目 | 位置 + 触发条件 + 可补性 |

## 通用字段纪律

**每一条 B / C / D 条目必须包含「容错窗口」和「失败信号」。** 容错窗口是玩家能承受的偏差范围（帧数、秒数、次数、血量阈值任意可量化者）；失败信号是"做错了会长什么样"。缺这两个字段的攻略等于没说清楚——玩家读完了还是不知道自己错在哪。

**每一条目必须带 `evidence` 数组。** 见 `evidence-protocol.md`。

## 配图纪律

攻略的图只有一个职责：**把「在哪」和「什么时候」这两件事从文字里解放出来。** 玩家拿着手机对着屏幕找位置时，一张带锚点的实拍图胜过三段描述。

| 层 | 最该配什么图 | 优先级 |
|----|--------------|--------|
| A 章节 | 章节场景全景，或本章不可逆节点的位置 | 中 |
| B 卡关点 | 失败处的位置图解（箭头标出安全点/危险判定区） | **高** |
| C BOSS | 每个阶段的关键前摇帧（`tell` 对应的那一秒） | **高** |
| D 隐藏要素 | 藏东西的那个角落，带周围参照物 | **高** |

三条硬规矩：

1. **图注必须说「看什么」**，不能写「第 3 章截图」。见 `evidence-protocol.md` 第五节的图注纪律。
2. **宁可留空，不可造假。** 拍不到就留待补图占位框，写明怎么拍到。用生成图冒充游戏截图是本技能明令禁止的，校验会直接拒绝。
3. **不确定位置就别画。** 机制示意图只用于表达**时间关系**（阶段顺序、血量区间、章节推进），不用于表达**空间位置**。不确定 BOSS 站在哪，就不给它画站位图。

有录像的话，用 `scripts/extract_frames.py` 按时间戳抽帧，产出的就是真实画面，直接挂 `kind=user_capture`：

```bash
python scripts/extract_frames.py C:/caps/boss2_phase2.mp4 --at 02:14 -o screenshots
```

## Layer A — 主线路线图

章节级推进顺序。**不写走位，不写"向左三格"**——那是 B 层的活。A 层的价值是让玩家知道全局结构和不可逆节点。

```jsonc
{
  "id": "ch3",
  "chapter": "✱ 第 3 章 · 沉没钟楼",
  "goal": "✱ 本章目标，一句话",              // 玩家读完知道"要干什么"
  "route": [                                  // 推进节点，顺序敏感，3-6 条
    "✱ 取得钩索后返回中央塔",
    "✱ 顶层触发钟摆机关"
  ],
  "time_estimate": "40-60 分钟",              // 需标 E 级，无证据时写「未验证」
  "unlock": ["二段跳"],                       // 本章解锁的能力，影响后续路线
  "missable": [                               // 错过即不可逆的内容，最重要的一栏
    { "what": "✱ 商人第一次出现时的限时商品", "window": "✱ 仅本章", "recoverable": false }
  ],
  "evidence": []
}
```

`missable` 是本层最有价值的一栏。玩家不介意绕路，介意的是"我永远拿不到了"。

## Layer B — 卡关点

```jsonc
{
  "id": "b2",
  "title": "✱ 卡关点名称（用玩家会遇到的现象命名，不用关卡编号）",
  "chapter": "✱ 第 3 章",
  "symptom": "✱ 失败信号：玩家反复出现的具体表现",   // 「总是在钟摆第三摆时被撞下去」
  "mechanic": "✱ 这里实际在考什么机制",             // 一句话点破，比十步走位有用
  "solution": {
    "思路": "✱ 一句话战略，先给思路再给步骤",
    "steps": ["✱ 步骤，动词开头，每步一个判断点"],
    "common_errors": ["✱ 常见错误及其后果"]
  },
  "tolerance": "✱ 容错窗口：如「第三摆后 0.5s 内起跳，窗口约 8 帧」",
  "evidence": []
}
```

写作顺序强制性：**思路 → 步骤 → 容错 → 常见错误。** 先给正确心智模型，玩家才能自己应对变体；直接给八步走位，换个场景就废了。

## Layer C — BOSS

BOSS 是唯一允许写到帧级/秒级的地方，因为读者在这里准备重打第十次。

```jsonc
{
  "id": "boss2",
  "name": "✱ BOSS 名称",
  "chapter": "✱ 第 4 章",
  "recommended": {
    "level": "✱ 建议等级/战力，无证据写「未验证」",
    "gear": "✱ 关键装备或抗性",
    "consumables": "✱ 建议携带的道具及数量"
  },
  "phases": [
    {
      "phase": 1,
      "hp_range": "✱ 100%-70%",
      "pattern": "✱ 招式组与循环顺序",
      "tell": "✱ 出招前摇的读法——看哪里、听什么",
      "punish": "✱ 安全输出窗口：哪一招后、能打几下",
      "risk": "✱ 低容错点：哪一招几乎没有容错"
    }
  ],
  "cheese": "✱ 低风险打法的存在性与代价（无则明确写「无」）",
  "evidence": []
}
```

`tell` 与 `punish` 是本层核心。玩家真正需要的不是招式表，是"我该盯着哪个部位、听到什么声音就准备躲、躲完之后有几秒能打"。

## Layer D — 隐藏要素

```jsonc
{
  "id": "c4",
  "name": "✱ 要素名称",
  "chapter": "✱ 第 5 章",
  "location": "✱ 位置描述，尽量给可复现的参照物",
  "trigger": "✱ 触发条件（时机/前置/顺序）",
  "missable": true,
  "recoverable": "✱ 错过后能否弥补，怎么补（不可补则明确写「不可补」）",
  "value": "✱ 奖励内容",
  "evidence": []
}
```

`missable` + `recoverable` 两栏必须联写。只说"在第 3 章能拿到"而不说"错过就没了"，是攻略最常见的失职。

## 待验证清单

无证据的内容不进正文，全部落到 `unverified`。格式强制为三问，不允许写"自行摸索""网上查查"：

```jsonc
{
  "question": "✱ 待确认的问题",
  "priority": "high | medium | low",
  "how_to_verify": {
    "where": "✱ 在游戏里哪个位置/节点",
    "what":  "✱ 具体做什么操作",
    "watch": "✱ 观察什么现象来判定结论"
  }
}
```

`priority` 判定标准：high = 影响主线推进或结局分歧；medium = 影响收集完成度；low = 仅影响效率或彩蛋。

## 禁止事项

1. **禁止无证据的走位指令。** 没有 E1-E3 支撑的路径描述不得出现在 A/B/C/D 正文。
2. **禁止编造数值。** 等级、血量、伤害、时长这类数字，没有证据就写"未验证"，不许估算后当事实写。
3. **禁止"多试几次"。** 这是失败定义缺失，不是攻略。
4. **禁止把版本敏感内容当永久事实。** 招式、数值、掉率随版本变化，句末标注 `[v1.03]`。
5. **禁止剧透倒灌。** B 层与 C 层默认不剧透后续剧情；必须提及时前置「剧透」标记。
6. **禁止跳过 A 层直接写 B 层。** 玩家需要知道这一步在全局的什么位置，否则读完仍然没有方向感。
