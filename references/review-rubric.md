# 评分卡：维度、权重、锚点与定级

## 通用锚定原则

**5 分不是"及格"，是"同品类中位水平"。** 所有维度的基准锚都定义在"同品类、同量级预算、同发售年代"的横向位置上，不定义在绝对质量上。这是让不同游戏的总分可以横向比较的唯一办法——否则给小体量独立游戏和大厂 3A 打分就是两套尺子。

第二条原则：**分数必须能被重算。** 给定同一份证据、同一套 rubric，任何人重新打分应得到相同结果。做不到这一点，说明锚点写得不够具体。

## 七个维度与固定权重

权重全局固定，禁止因游戏类型、厂商规模、价格档位调整。类型差异通过"该维度的锚点解释"处理，不通过改权重处理。

| 维度 | id | 权重 | 它回答的问题 |
|------|-----|------|--------------|
| 核心循环与玩法深度 | `core_loop` | 0.20 | 0-30 秒那一下好不好玩？30 分钟后还有新决策吗？ |
| 关卡与内容设计 | `level_design` | 0.18 | 关卡在教什么、考什么？节奏有没有起伏？ |
| 操作手感与反馈通道 | `feel_feedback` | 0.15 | 输入到反馈的延迟、清晰度、视听触一致性 |
| 系统与数值健康度 | `systems_balance` | 0.14 | 有没有通胀？有没有唯一解？付费点是否破坏平衡？ |
| 视听表现与美术方向 | `presentation` | 0.12 | 音画是否服务玩法？方向是否自洽？ |
| 技术稳定性与性能 | `tech_stability` | 0.11 | 帧率、加载、崩溃、读取、平台适配 |
| 内容量与性价比 | `value_content` | 0.10 | 单位时间成本、重复内容占比、DLC 策略 |

权重和必须为 1.00，脚本强制校验。

## 维度锚点表

每维度给出 3 / 5 / 7 / 9 四个锚点。打分时选取最接近的锚点，可上下浮动 1 分，浮动必须写理由。**每维度至少填一条加分锚点和一条扣分锚点**，锚点必须是可观察现象，不能是形容词。

### core_loop（核心循环与玩法深度）

| 分 | 锚点 |
|----|------|
| 3 | 循环单一，前 30 分钟已穷尽所有决策类型；后续仅靠数值堆叠延长 |
| 5 | 有清晰循环与一条进阶轴，中期开始出现重复感，靠内容量而非机制撑时长 |
| 7 | 循环内存在 2 条以上互相影响的决策轴，玩家会主动规划而非被动反应 |
| 9 | 循环自解释、自生长：机制间产生计划外组合，玩家社群能发明设计者未预设的解法 |

### level_design（关卡与内容设计）

| 分 | 锚点 |
|----|------|
| 3 | 关卡为通道而非设计：无教学、无变奏，难度靠增伤与堆怪 |
| 5 | 结构完整、节奏平稳，有明显"教学-练习-考核"痕迹但变奏有限 |
| 7 | 每关有明确考察的单一技能，节奏有起伏，存在允许跳过的合理捷径 |
| 9 | 关卡同时承担教学、叙事、难度曲线三重职能，重复挑战仍有新理解 |

### feel_feedback（操作手感与反馈通道）

诊断口诀：**先查反馈通道，再怀疑机制。** 手感问题 80% 出在视觉/音频/触觉反馈的时序与强度，不出在输入逻辑。

| 分 | 锚点 |
|----|------|
| 3 | 输入延迟可感知；命中/受击缺乏视听确认；玩家需要看 UI 数字才知道发生了什么 |
| 5 | 反馈到位但不突出，四通道（视/听/触觉/UI）基本齐备、时序正确 |
| 7 | 反馈有明确层次：轻击与重击在视听上可分辨，受击方向、伤害量级可在不看 UI 时读出一条 |
| 9 | 反馈本身构成信息通道：老玩家仅凭音效与镜头语言即可判断格挡成功、暴击、无敌帧剩余 |

### systems_balance（系统与数值健康度）

强制自检：**列出所有 source，逐个找对应 sink。** 任何 source 找不到 sink，就是通胀定时炸弹，直接进扣分锚点。

| 分 | 锚点 |
|----|------|
| 3 | 存在主导策略（唯一解）；资源产出远大于消耗；付费可直购强度 |
| 5 | 无明显破坏性失衡，存在 1-2 套较优解但代价可接受；付费不直接影响强度 |
| 7 | 多套 build 各有适用场景，存在软性 counter；资源消耗随进度同步增长 |
| 9 | 各系统互相形成负反馈：强 build 带来资源压力或操作成本，长期无单一最优解 |

### presentation（视听表现与美术方向）

| 分 | 锚点 |
|----|------|
| 3 | 视听与玩法脱节；美术方向内部不一致；音乐循环点可感知 |
| 5 | 完成度高、风格统一，但属于行业通用表达，记忆点有限 |
| 7 | 美术方向明确服务玩法（可读性、辨识度、氛围），关键场景有设计意图 |
| 9 | 视听承担玩法功能（用颜色/音高编码游戏状态），脱离玩法单看仍成立 |

### tech_stability（技术稳定性与性能）

必测项：目标平台实测帧率与 1% low、加载时长、快速旅行/重开耗时、崩溃与存档损坏、首日补丁状态、手柄/键鼠/触屏适配。

| 分 | 锚点 |
|----|------|
| 3 | 常态掉帧或崩溃可复现；核心流程有阻塞性 bug；存档风险存在 |
| 5 | 达标帧率下有偶发波动，加载可接受，无阻塞性 bug |
| 7 | 帧率稳定、加载快、支持丰富的辅助功能与画面选项 |
| 9 | 多平台表现一致且可调项透明，辅助功能达到行业领先，热更新不打断游玩 |

### value_content（内容量与性价比）

必测项：主线时长、支线占比、重复内容占比、二周目价值、DLC 与内购总价、单位小时成本。

| 分 | 锚点 |
|----|------|
| 3 | 时长短且重复度高，DLC 切走本体内容，单位小时成本高于同品类中位 |
| 5 | 内容量与定价匹配，存在可选重复内容但不构成强制 grind |
| 7 | 主线扎实、支线有独立设计意图，二周目或高难模式提供实质变化 |
| 9 | 定价保守而内容超量，重复内容可跳过，后续更新为增量而非拆分 |

## 权重与总分

总分 = Σ(维度分 × 权重)，保留一位小数。由 `scripts/build_report.py` 计算，禁止手算后写入。

## 定级区间

| 总分 | 定级 | 说明 |
|------|------|------|
| 9.0-10.0 | 标杆级 | 定义了品类的表达上限，可作横向比较基准 |
| 8.0-8.9 | 强烈推荐 | 核心体验优秀，缺陷不影响主体乐趣 |
| 7.0-7.9 | 推荐 | 明显优点 + 明显短板，是否合适取决于玩家口味 |
| 6.0-6.9 | 尚可 | 各方面达标但无突出项，或单一维度严重拖累 |
| 5.0-5.9 | 谨慎 | 存在影响核心体验的结构性问题 |
| < 5.0 | 不推荐 | 核心循环或稳定性不成立，非口味问题 |

## 证据基础与总分上限

这是"公正"最容易被忽略的部分：**同一款游戏，玩 2 小时和玩 40 小时不该给出同等信心的结论。** 按证据基础上限封顶。

| 证据基础 | 允许产出 | 总分上限 |
|----------|----------|----------|
| 通关主线 + 时长 ≥ 15h + 素材可核 | 完整评测 + 定级 | 10.0 |
| 通关主线 + 时长 < 15h | 完整评测 + 定级，须标注覆盖范围 | 8.5 |
| 通关主线 + 时长或素材未获本地核实 | 完整评测 + 定级，须在首屏写明哪一项未核实 | 8.5 |
| 未通关，已进入核心循环 | 维度分 + 定级，须标注覆盖范围 | 7.5 |
| 游玩 < 3h 或未进入核心循环 | 仅维度分，禁止输出总分与定级 | 不出总分 |
| 未游玩，纯资料评测 | 资料评测版，禁止定级结论 | 6.5 |

**为什么"通关 + 时长未核实"不能拿 10.0**：10.0 那一档的三项条件里，「素材可核」是唯一能让第三方复核的部分。玩家自述的时长不可复现，只靠自述就上 10.0，等于把"公正"交给一句无法验证的话。上限压到 8.5，同时把缺项写在报告首屏——分数降了，但读者知道为什么降。

封顶由脚本执行：数据中填 `evidence_base` 字段，脚本按上表截断并输出提示。

## 公正性自查清单

打分前逐条过，把结果写入 `bias_audit` 数组（字段：`risk` / `finding` / `action`）。任何一条未核查，不允许输出总分。

| # | 风险 | 检查方式 | 处置 |
|---|------|----------|------|
| 1 | 利益相关 | 是否与发行商/开发方存在送测、赞助、合作关系 | 在报告首屏声明，存在关系时总分上限 6.5 |
| 2 | 平台偏好 | 主机/PC/移动的操作习惯是否污染了"手感"评价 | 把"操作手感"与"平台适配"拆成两条锚点，后者计入 `tech_stability` |
| 3 | 系列情怀 | 是否因前作或系列历史给出加成或惩罚 | 系列对比单独成节，**分数不进总分** |
| 4 | 素材污染 | 是否把宣传片、媒体先行评测、KOL 观点当成事实 | 只把可验证事实计入评分，宣传信息不得作为加分锚点 |
| 5 | 时长偏差 | 结论基于前几小时还是完整体验 | 强制声明评测覆盖段（如"基于前 8 小时，未进入后期"） |
| 6 | 规模偏差 | 是否因"独立游戏"而宽容、因"大厂"而严苛 | rubric 与权重对所有游戏一致，不因厂商规模调整 |
| 7 | 首发情绪 | 是否受首发舆情、评分网站分数、退票潮影响 | 不引用其他平台分数作为锚点；只记录可观察现象 |

## 双来源规则

支撑 E3 等级结论时：

- **一手来源**（官方补丁说明、官方 Wiki、开发者公告、平台商店页）：单一来源可支撑。
- **二手来源**（攻略站、社区帖、媒体评测）：**至少两个相互独立来源**，且两来源需在关键事实上一致。不一致时降级为 E4 并写明分歧点。

## 写作纪律

- 每个结论句后必须能对应到一条锚点或一份证据，对不上就删。
- 禁止形容词单独成句（"打击感很棒"不是结论，"重击的命中停顿为 8 帧、比轻击长 5 帧，受击方向可从音效声道分辨"才是）。
- 禁止把"我不喜欢"写成"设计错误"。区分：个人口味 / 目标用户错配 / 设计缺陷。三者处置不同。
- 版本敏感结论必须在句末标注 `[v1.03]`，版本变更后需重测。
